## Seguridad y límites

No se guarda el token en localStorage, sessionStorage, cookies o URL, ni se registran solicitudes.
No se incorporan claves de backend al bundle. El cliente requiere HTTPS y certificado confiable;
las portadas se descargan con Bearer y sus URL de objeto se revocan. La API mantiene autorización.
El control de patrones de secretos tiene alcance conocido y no detecta cualquier secreto posible.

La inspección visual mediante navegador integrado no pudo conectar con el servidor local en esta
sesión. El diseño contiene reglas de escritorio/móvil; esa declaración no equivale a QA visual
ejecutado. El contenedor y el recorrido de punta a punta con API/base/HTTPS deben comprobarse
con infra. T-22 sigue con aceptación integrada pendiente: los mocks no acreditan esa integración.

## Recorrido de aceptación pendiente con infra

1. Aplicar migraciones explícitas y arrancar API/admin, React y proxy HTTPS confiable.
2. Admin: login, crear/editar libro, subir/quitar portada y crear bibliotecario.
3. Bibliotecario: login, buscar catálogo, crear socio, prestar 1–3 libros y devolver cada línea.
4. Verificar conflictos del servidor (sin existencias, duplicado, límite, vencido y doble devolución).
5. Consultar vencidos y reporte admin; librarian recibe 403 si intenta el reporte directamente.
6. Revisar teclado, contraste, foco, scroll y disposición en escritorio y móvil con datos reales.

No cambia el alcance del producto ni el corte original de entrega. Esta implementación es posterior
al corte; no certifica elegibilidad ni cierre de T-20/T-21/T-23 o RNF-1.
